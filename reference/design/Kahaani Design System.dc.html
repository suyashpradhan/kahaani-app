One warm, quiet system — built so a voice stays the loudest thing on the screen.

05 State matrix
Buttons
default → hover (−6% lightness) → pressed (translateY 1px) → disabled (#EADDD1 / #A08C7C, no shadow) → loading (spinner replaces icon, label becomes present tense: "Keeping…")
Audio
ready (play) → loading (spinner in the circle, waveform at 50% opacity) → playing (pause icon, played bars fill) → paused (position held) → unavailable (dashed border, "isn't ready yet", no button)
Recording
permission → ready → recording (rings + live bars + timer) → stopping (breathing circle, ~1.3s) → failed (silence detected: nothing lost, try again)
Translation
loading (language chip stays tappable, transcript skeleton at 3 lines) → available → unavailable (read-only translation, or "not ready yet" if neither text nor audio landed). The original is never in a loading state — it exists the moment recording stops.

08 Assets
Fonts
Tiro Devanagari Hindi, Tiro Kannada (ship weight 400 + italic only). Expansion: Tiro Bangla, Tiro Gurmukhi, Tiro Tamil, Tiro Telugu; Noto Serif Gujarati / Malayalam / Odia. UI: Hanken Grotesk 400/500/600 + Noto Sans Devanagari, Noto Sans Kannada. Load per-script, on demand — never all nine at once.
Icons — 19 glyphs
mic · mic_off · play_arrow · pause · stop_circle · graphic_eq · volume_up · volume_off · hearing · ios_share · arrow_back · arrow_forward · add · check · check_circle · radio_button_unchecked · progress_activity · refresh · info
Material Symbols Rounded 300. Subset to these 19, or inline as an SVG sprite if the font is heavy on 3G. No decorative icons, no sparkles.
Images
Only the family's own photographs: one portrait per person, square source ≥256px, always masked to a circle (46 / 54 / 64px). Prototype uses a striped placeholder. No stock photography, no illustration, no decorative motifs.
Audio
Original: whatever MediaRecorder gives (audio/webm;codecs=opus, mono) stored untouched and served as-is. Optional reading track: mp3/m4a. Peaks: 44 normalised floats per track, computed once at upload — the UI never decodes audio to draw.

One shared <audio> per page and a single "now playing" id in context — the original and a reading track can never sound at once. Separate positions per track; never carry a playhead across languages. No autoplay, ever.
Render the memory page the moment original + original transcript exist. Translations fill in by polling every 3s; a missing key renders the "not ready yet" block, never a spinner over the page. Nothing about the original may depend on a translation succeeding.
Language lives in the URL — /m/:id?lang=en — so a WhatsApp link can open straight into English while ಕನ್ನಡ · Original stays one tap away. Share sheet copies the link with the recipient's language pre-set.
Screen state is local useReducer; only "keeping" is server work. Waveforms are divs, timers are setInterval + tabular mono. No animation library, no canvas, no audio-analysis on the client — the whole prototype is reproducible in a day.

12 Two experiences, one product
The host curates the memory. The storyteller only tells it. Every product decision below follows from that one sentence — and from its corollary: Kahaani should feel like receiving a question from someone you love, not a task from an app.

Processing — her job ends when the audio lands
The link is the configuration
One MemoryPrompt per link: id, storyteller, host, promptText, promptAudio, storytellerLanguage, createdAt, status, privateRecordingUrl. Because the token carries all of it, her page has nothing to ask her. Future prompt types — photo + question, video, an object or a place — extend the same record; the hackathon ships question + optional host voice only.
The host’s voice is the P0 feature
“Say it in your own voice” is not a nice-to-have — it is what turns a form into a family message. States: idle → recording (stop, live bars, timer) → attached (play, redo). Generating a spoken version is documented as later, and marked as later in the UI.
Elder scale, unchanged
Question 35/1.45 · reading copy 18–21 · primary button 92px with a 24px label · mic visual 112–118px · timer 40px tabular mono. One primary action per screen, pinned to the bottom, never moving between states.
Permission, quietly
No tutorial in the happy path. “Tap and tell me” requests the microphone and goes straight to recording. Only refusal produces a screen: “The microphone isn’t on.” · Try again · Ask Suyash for help — a phone call, two lines, no settings walkthrough.
Accidental finish
Under 10 seconds only: “Finished already?” with Keep recording as the primary. Over 10 seconds it never appears.
Sharing is WhatsApp-first
Send on WhatsApp is primary; Copy link sits on the URL row with a Copied confirmation. SMS and QR are named as future paths. No iMessage-specific patterns, no app install, no sign-in for her.
13 Family Space — the host's product
Three objects, no navigation structure: people, questions, memories. The family home leads with faces at 72px and names at 22px in the story serif; counts sit underneath at 12.5px because a person outranks their statistics. There is no sidebar, no tab bar, no filter row, no metric — if a screen starts to look like a tracker, the people have shrunk.
Family home
Family name in the story serif · a 2×2 grid of people, the one you're waiting on carrying a small warm "waiting" mark · the answered memory arriving at the top as a card, not a notification · two quiet recent listens · Ask someone something as the only filled button, with Record together beneath it as text.
Person
Her name at 34px, relationship and place beneath. One row owns her preferred language — "She hears Kahaani in ಕನ್ನಡ · Change" — because that setting is the host's, never hers. Then Her stories: title in serif, a 14-bar waveform, language and duration; tapping opens the Memory page. Listening is the invitation, not a table.
Ask · two steps, never more
Step 1 — the question. Seven categories in a scrolling row; each shows only two or three curated prompts, each in English and in her script, so the host can see what she'll actually read. "Write my own question" opens one textarea. Step 2 — how she hears it. "Say it myself" is the marked P0 path: record, play back, record again. Nothing is required.
Share
"Ready for Ajji" over a truthful mirror of her page — the same avatar line, the same question, the host's audio with its real duration. A padlocked URL row with Copy. Send on WhatsApp filled, Copy private link outlined, and one line of reassurance: no app or account needed.
Pending, kept human
"Waiting for Ajji" · her question in her script · "Sent today" · one Send again. No status pills, no assignees, no due dates, no progress bar. A family is not a backlog.
The reward
When she answers, the pending block becomes the memory in the same slot: a filled heart, "Ajji answered", the title in serif, "not heard yet", and a 48px play button. Same position, same card geometry — the transformation is the reward, so it must not be a toast.

14 Changelog — the architecture change
Removed from the storyteller
The language switcher · “Another question” · the sender information card · the two-step microphone tutorial and its illustrated pre-permission screen · the “recording together” banner · playback of her own recording on the success screen · the separate “you can close this page” screen (now one line on Done) · every trace of categories.
Moved to the host
Question choice and custom wording · her interface language · the spoken prompt, now the host’s own recording rather than a synthesised reading · link creation and sharing · reminders · everything about titles, translation and organisation. New host screens: Family space, Storyteller profile, Ask, Share.
Preserved untouched
Warm paper foundation and the whole token set · clay for her original voice, slate for machine translation · the Memory page in full, including “Her original voice” vs “Understand in English” · AudioPlayer, Waveform, LanguageSwitcher, TranscriptBlock, MemoryPreview, PersonIdentity · the desktop two-column Memory layout · the illustration language, the motif, and all six motion patterns.
Needs implementation work
RecordingControl splits into a host variant (48px inline, in the Ask card) and a storyteller variant (112px, full screen). StoryPrompt becomes two components: an editable host chooser and a read-only storyteller display. New: StorytellerRow, PendingPrompt, ShareSheet, LinkPreview. ProcessingState is now host-only — the storyteller never waits on it. Routing splits into an authenticated app and an unauthenticated /story/{token} route with its own minimal layout.
The test for any future control: does the storyteller need this to tell THIS story? If not, it belongs to the host. Applied honestly, that question is what keeps her page at three states while the family app grows.

Cues are memory triggers, not decoration: suggestive object groups on one ground line, never a scene of her life. Exactly one per screen, at 158×99, 0.95 opacity, with a single moving part — a swaying plant, three staggered steam wisps, one flame. Nothing in the illustration is ever the only carrier of meaning.
Android & mobile behaviour
Design width 390; verified to 844 with no vertical scroll on any state, in Hindi, Kannada and English. Pinned actions carry flex:none so a long question scrolls its own block instead of squeezing the microphone. Respect env(safe-area-inset-bottom) — Chrome’s URL bar collapses on scroll and the button must not travel with it. No swipe, no long-press, no gesture anywhere. Test the WhatsApp in-app browser explicitly: some Android builds block getUserMedia outright, in which case the mic-failure screen is the fallback surface and should offer “open in Chrome”.
React implementation
/story/:token renders outside the app shell — no providers, no auth, no router chrome. The token resolves to {storyteller, host, promptText, promptAudio, storytellerLanguage, category}; category is the only input the cue needs. State is a three-value enum plus two exceptions — a useReducer, not a store. Call getUserMedia inside the microphone tap; on rejection go to the failure state, never to a modal. Upload on stop; on network failure keep the Blob in IndexedDB and retry — she has already seen Done. Under 10s, show the “finished already?” confirmation once, never twice.
Assets retained, nothing new invented
The listening visual, the settle animation, the childhood-home and kitchen clusters, the motif, and all six motion patterns come straight from the illustration system. New this pass: four cue clusters (work, love, traditions, advice) built on the identical 128×80 artboard, 2px clay stroke, one ground line, ≤12 paths, same palette. Type, colour, radii, elevation and the elder scale are unchanged.
Things intentionally removed from the storyteller experience
Language switcher · category chips · “another question” · question library · a sender information card · the pre-permission tutorial and its two-step illustration · pause · delete · re-take before finishing · playback speed · microphone or audio settings · transcript · translation · any language toggle · story title · tagging · a story list or archive · “record another” suggestions · recommendations · account creation · sign-in · app install prompt · onboarding · progress percentages · processing or model status · error codes · toasts · a bottom nav · a back button on the question screen · Kahaani branding above 14px · more than one illustration per screen · any gesture.
Each of these has a home in the host experience, or no home at all. Before adding anything to this page, count her decisions again: if the number goes above three, the thing belongs to the family app.
